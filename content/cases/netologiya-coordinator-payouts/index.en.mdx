## Problem

There was no two-step approval process for paying course coordinators in a single environment. Accountants and budget controllers worked in different tools, which made the job awkward for everyone involved.

## Solution

### Stage 1. Discovery

Since no process map existed, the first job was to understand how things actually worked. The difficulty was that every stakeholder only knew their own part of it, so discovery took a long time. Understanding the specifics of each group's work added another layer. In the end I produced as-is and to-be process maps.

As-is and to-be process maps

![As-is and to-be process maps](./02.png)

### Stage 2. Prototype and testing

I skipped lo-fi prototypes because speed was the priority, and because I was working with the Ant Design library. I tested a clickable prototype with all user groups. That surfaced several cases we had not accounted for, so some changes went in.

Prototype

![Prototype](./03.png)

### Stage 3. Specification

Once the changes were in, I wrote the specification for the engineers.

Specification

![Specification](./04.png)

## Outcome

Together with the team we built a new process from scratch, covering three user groups, and moved the whole flow out of three separate tools into one admin panel. The feedback was positive.
