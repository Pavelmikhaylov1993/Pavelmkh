# Как править контент сайта

Эта папка — весь текст и все картинки портфолио. Чтобы что-то изменить, программировать не нужно: правите файлы здесь, коммитите, и через пару минут сайт обновляется сам.

Сайт живёт по адресу <https://nkonovalov1990.github.io/Pavelmkh/>

---

## Что где лежит

```
content/cases/                        ← все кейсы, по папке на каждый
  netologiya-payment-ux/
    index.mdx                         ← текст кейса
    01.png, 02.png, …                 ← его картинки
  cian-client-info/
    index.mdx
    01.png …
```

Имя папки — это адрес кейса на сайте. Папка `netologiya-payment-ux` открывается по адресу `…/Pavelmkh/case/netologiya-payment-ux/`.

Данные о себе — имя, роль, описание и контакты — лежат отдельно, в файле `src/lib/site.ts`. Он выглядит как обычный список, править можно смело: там просто строки в кавычках. Контакты оттуда показываются в двух местах сразу: кнопками в шапке главной страницы и в подвале на всех страницах.

Резюме в PDF: `public/Pavel_Mikhaylov_CV.pdf`. Чтобы обновить, положите новый файл с тем же именем.

## Как поправить текст в существующем кейсе

Откройте `content/cases/<имя-кейса>/index.mdx` и правьте. Файл состоит из двух частей.

**Верхняя часть, между двумя `---`** — это карточка кейса: то, что видно в списке на главной и в шапке страницы кейса.

```yaml
---
title: "Улучшение UX в блоке оплаты"
company: "Нетология"
order: 2
summary: "Разобрал флоу оформления заказа и переработал блок оплаты."
role:
  - "Исследование"
  - "Интервью"
outcome: "Время работы менеджера с одним заказом сократилось вдвое"
metrics: [{value: "−50%", label: "времени на один заказ"}]
cover: "./01.png"
---
```

| Поле | Что это |
|---|---|
| `title` | Название кейса. Без названия компании — она отдельным полем |
| `company` | Компания: Нетология, Циан, Деловые Линии |
| `order` | Порядок в списке на главной. 1 идёт первым |
| `summary` | Текст на карточке. Максимум 200 символов, иначе сборка не пройдёт |
| `role` | Что вы делали. Каждый пункт с новой строки после дефиса |
| `outcome` | Результат одной фразой. Показывается и на карточке, и в шапке кейса |
| `metrics` | Цифры результата. Можно оставить пустым: `metrics: []` |
| `cover` | Картинка для карточки. Обычно `"./01.png"` |

Кавычки вокруг текста обязательны. Если внутри текста нужны кавычки, используйте «ёлочки».

**Нижняя часть, после второго `---`** — сам текст кейса.

```markdown
## Проблема

Обычный абзац текста.

### Этап 1. Исследование

![Что на картинке](./02.png)
```

- `##` — крупный раздел: «Проблема», «Решение», «Результат»
- `###` — подраздел внутри: «Этап 1…», «Этап 2…»
- `**жирный**`, `*курсив*`
- Картинка: `![описание](./имя-файла.png)`

Уровни заголовков не перепрыгивайте: после `##` может идти `###`, но не сразу `####`.

---

## Про подписи к картинкам

Текст в квадратных скобках — `![Старый интерфейс](./02.png)` — это не подпись под картинкой, её не видно. Это описание для незрячих людей и для поиска. **Оно обязательно, пустым оставлять нельзя** — сборка не пройдёт.

Пишите то, что на картинке: «Старый интерфейс заказа», «Схема процесса AS IS», «Lo-Fi макеты». Не «картинка» и не «скриншот».

## Как добавить новый кейс

1. Создайте папку в `content/cases/`. Имя — латиницей, строчными, слова через дефис: `cian-chat-redesign`. Оно станет адресом страницы, так что менять его потом нежелательно — старые ссылки перестанут работать.

2. Положите туда картинки. Называйте по порядку: `01.png`, `02.png`. Формат любой: PNG, JPG, WebP.

3. Создайте в этой же папке файл `index.mdx` и вставьте заготовку:

```markdown
---
title: "Название кейса"
company: "Компания"
order: 7
summary: "Одно-два предложения о сути. До 200 символов."
role:
  - "Исследование"
  - "Проектирование"
outcome: "Что получилось в итоге, одной фразой"
metrics: []
cover: "./01.png"
---

![Описание первой картинки](./01.png)

## Задача

Текст.

## Решение

Текст.

## Результат

Текст.
```

4. Поставьте `order` больше, чем у остальных кейсов, чтобы новый встал в конец. Или поменяйте `order` у других, если хотите поставить его выше.

5. Закоммитьте. Сайт обновится сам.

Ничего больше настраивать не нужно: страница кейса, ссылка с главной и переходы «предыдущий / следующий» появятся автоматически.

## Как убрать кейс

Два способа.

**Спрятать, но сохранить.** Добавьте в верхнюю часть строку `draft: true`. Кейс исчезнет с сайта, но останется в папке. Убрать строку — вернётся.

**Удалить совсем.** Удалите папку кейса целиком.

## Если сборка не прошла

После коммита GitHub проверяет сайт и, если что-то не так, присылает письмо и красный крестик у коммита. Сайт при этом не ломается — остаётся предыдущая рабочая версия.

Что бывает чаще всего:

| Сообщение | Что случилось |
|---|---|
| `summary: String must contain at most 200 character(s)` | Слишком длинное `summary`. Сократите |
| `role: Array must contain at least 1 element(s)` | Пустой список `role` |
| `Could not find requested image` | В `cover` или в тексте указан файл, которого нет в папке. Проверьте имя и расширение |
| `Required` рядом с названием поля | Забыто обязательное поле в верхней части |
| Тест `AC-4` про `alt` | У какой-то картинки пустое описание в квадратных скобках |

В сообщении об ошибке всегда указан файл — с него и начинайте.

## Проверить перед коммитом

Если хочется убедиться заранее, в терминале из корня проекта:

```bash
npm run dev
```

Откроется локальная копия сайта, где сразу видно изменения. Остановить — `Ctrl+C`.

Проверить всё то же, что проверяет GitHub:

```bash
npm test && npm run test:e2e
```
