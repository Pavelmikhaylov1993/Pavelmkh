# Инструкция для ИИ-агента

Сайт-портфолио продуктового дизайнера Павла Михайлова. Статика на Astro 5, хостинг GitHub Pages.
Живой адрес: <https://nkonovalov1990.github.io/Pavelmkh/>

Читай этот файл целиком перед первой правкой. Здесь собраны ловушки, каждая из которых
уже один раз сломала сборку или дала зелёный тест, который ничего не проверял.

## Команды

```bash
npm run dev        # локальная разработка
npm run build      # сборка в dist/, 8 страниц
npm test           # Vitest, 51 тест
npm run test:e2e   # Playwright, 142 теста; сам собирает проект и поднимает preview
```

E2E гоняются против **собранного** сайта с настоящим base `/Pavelmkh`, а не против dev-сервера.
Это не придирка: `GET /` на собранном сайте отдаёт 404, а `GET /Pavelmkh/` — 200. Тесты,
настроенные на `/`, проходили бы вхолостую.

Прогнать тот же набор против живого сайта после деплоя:

```bash
PLAYWRIGHT_BASE_URL=https://nkonovalov1990.github.io/Pavelmkh/ npm run test:e2e
```

## Устройство

```
content/cases/<slug>/index.mdx   контент кейса; картинки лежат рядом, путь ./NN.png
content/README.md                инструкция для человека, правящего тексты
src/lib/site.ts                  профиль: имя, био, метрики, контакты. Единственный источник
src/lib/case-schema.ts           Zod-схема frontmatter. Чистая, без astro:content
src/lib/cases.ts                 getSortedCases() — единственное место, задающее порядок кейсов
src/lib/utils.ts                 cn(), withBase() — единственное знание о base path
src/content.config.ts            коллекция; generateId срезает «/index» из идентификатора
src/components/*.astro           вёрстка без клиентского JS
src/components/react/            ThemeToggle и Lightbox — единственные React-острова
src/components/ui/               примитивы shadcn, положены руками
src/layouts/                     BaseLayout и CaseLayout
src/pages/                       index, case/[...slug], 404
scripts/import-yonote.mjs        разовый импорт из вики. Уже отработал, в проде не нужен
docs/superpowers/                спека с критериями приёмки AC-1…AC-29 и план реализации
.superpowers/sdd/progress.md     журнал: что и почему решено, находки всех ревью
```

Границы: `site.ts` не знает про компоненты, контент не знает про вёрстку, компоненты
получают данные пропсами. Данные из коллекции собирают только страницы в `src/pages/`.

## Жёсткие ограничения

Нарушение любого из них ломает прод или тихо портит качество.

### Версии прибиты к линейке Astro 5

`astro@5.18.2`, `@astrojs/react@5.0.7`, `@astrojs/mdx@4.3.14`, `@astrojs/sitemap@3.7.3`,
`tailwindcss@4.3.3`, корневой `zod@3.25.76`.

Свежие мажоры интеграций собраны под Astro 6/7 и ломают сборку. **`@astrojs/react` не
объявляет peer-зависимость от astro ни в одной версии** — npm такой конфликт не поймает,
проверяй совместимость руками при каждом обновлении.

**Корневой `zod` обязан оставаться на 3.x.** Astro тянет свою копию zod v3, и хелпер
`image()` отдаёт схему именно v3. Корневой v4 несовместим с ней в `.extend()`. Ломается
не сразу: пока коллекция пуста, сборка проходит, падает на первом реальном кейсе.

### `npx shadcn@latest` использовать нельзя

CLI версии 4.15 ставит пресет `base-nova` на Base UI вместо Radix, переписывает
`src/styles/global.css` целиком — меняет Inter на Geist и добавляет чужие токены — и
**удаляет `withBase()` из `src/lib/utils.ts`**.

Нужен новый примитив — копируй руками из реестра `new-york` в `src/components/ui/`.
Radix стоит одним пакетом `radix-ui`.

### Правило ссылок асимметрично

- Внутренние пути и файлы из `public/` — **только** через `withBase()`.
- Внешние абсолютные URL — **никогда** через `withBase()`.

`withBase()` не проверяет протокол: `withBase('https://t.me/Pavelmkh')` вернёт
`/Pavelmkh/https://t.me/Pavelmkh`, и ссылка сломается молча. Оба направления ошибки
ловит тест `AC-27` в `tests/e2e/budget.spec.ts` — он сканирует весь собранный HTML.

### Шрифт Inter только self-hosted

Через `@fontsource-variable/inter`. Обращений к Google Fonts или любому CDN быть не должно.

### Язык интерфейса только русский

Включая `aria-label` и подписи внутри примитивов shadcn.

## Что неочевидно и уже стоило времени

**Тесты с `.astro`-компонентами требуют окружения node.** `experimental_AstroContainer`
ломается под глобальным jsdom: «instanceof Uint8Array is incorrectly false». В
`tests/unit/case-card.test.ts` стоит директива `// @vitest-environment node`.

**Клик по острову без ожидания гидратации — гонка.** До гидратации кнопка есть в
разметке, обработчика нет, клик уходит в пустоту, а Playwright проверяет только
доступность DOM-узла. Astro снимает атрибут `ssr` с `<astro-island>` ровно в момент
гидратации:

```ts
await page.waitForSelector('astro-island:not([ssr])');
```

Гонка проявляется только под нагрузкой полного прогона — в одиночном запуске теста её не видно.

**`ThemeToggle` намеренно без состояния.** Тема живёт в классе на `<html>`, который ставит
инлайн-скрипт до первой отрисовки. Если продублировать её в React-стейте, `client:load`
отрендерит остров на сборке со стартовым значением, и в статическом HTML у пользователя с
тёмной темой окажутся иконка и подпись от светлой. Обе иконки лежат в разметке, видимость
через `dark:`.

**`Lightbox` обязан всегда рендерить host-контейнер.** Пустой `<div>` вокруг диалога
выглядит бессмысленным, но без него в закрытом состоянии компонент не рендерит ни одного
узла, `client:visible` нечего наблюдать, и остров не гидратируется никогда. Остров стоит
первым внутри `.prose-case`, а не в конце страницы — иначе он оживал бы только когда
читатель домотал ниже всех картинок.

**Мобильный проект Playwright эмулирует тач.** `page.mouse.click()` до обработчиков Radix
не доходит. Кликай по элементу локатором.

**Вьюпорт мобильного проекта задан явно.** У дескриптора `iPhone 13` он 390×664, а 390×844
из спеки — это поле `screen`, которое на вёрстку не влияет. Плюс дескриптор требует
WebKit, а ставится только chromium, поэтому `browserName` тоже задан явно.

**Бюджет JS считается по графу импортов.** Считать по вхождению имени файла в HTML нельзя:
транзитивные чанки в разметке не упомянуты, но браузер качает их обязательно. Разница была
71 против 86 КБ, и любая зависимость, общая двум островам, попадала как раз в невидимый чанк.

**`npm ci` строже `npm install`, и CI это ловит, а локальная машина нет.** Однажды в
`package-lock.json` оказалась запись `node_modules/rolldown/node_modules/@rolldown/binding-win32-arm64-msvc`
с единственным полем `{"optional": true}` — без `version`, `resolved` и `integrity`.
`npm install` такое проглатывает, `npm ci` падает с `npm error Invalid Version:` без
указания пакета. Локально ошибка не воспроизводилась, потому что запись добиралась из
тёплого кеша npm; на CI кеш пустой.

Если CI падает на `npm ci`, а локально всё ставится — ищи в локе записи без версии:

```bash
node -e "const l=require('./package-lock.json');
console.log(Object.entries(l.packages).filter(([k,v])=>k!=='' && v.version===undefined && !v.link).map(([k])=>k))"
```

Воспроизвести условия CI можно пустым кешем: `npm ci --cache /tmp/empty-cache`.

**`toBeInViewport()` не замечает перекрытия.** Он меряет только пересечение с вьюпортом,
поэтому элемент, полностью накрытый липкой шапкой, для него видим. Где это важно —
сравнивай координаты.

## Как писать тесты

Каждый тест начинается с номера критерия приёмки из спеки: `test('AC-7: ...', ...)`.
Полный список — `docs/superpowers/specs/2026-07-27-designer-portfolio-design.md`, раздел 6.

Разделение слоёв: Vitest — схемы, утилиты, React-компоненты, отдельные `.astro` через
контейнер. Playwright — всё, что требует настоящей страницы: навигация, адаптив, SEO,
доступность, бюджеты.

**Главное требование к тесту — чтобы он мог покраснеть.** В этом проекте уже находили
четыре теста, зелёных по неверной причине:

- проверял наличие `h1` и проходил на странице 404, куда уводил битый переход;
- проверял непустоту поля, непустоту которого и так гарантирует Zod-схема;
- использовал `toBeInViewport()` там, где элемент был накрыт шапкой;
- сравнивал заголовки страниц только с заголовком главной, поэтому дубли между кейсами прошли бы.

Перед тем как считать тест написанным, спроси себя: какая правка кода его уронит? Если
ответа нет — тест не нужен.

Проверяй конкретные значения, а не факт наличия. `toHaveText('Информация о клиенте в чатах')`
вместо `toBeVisible()`.

## Осознанные решения, которые не надо «чинить»

- **Тексты кейсов перенесены из вики дословно**, включая опечатки и разговорные обороты.
  Вычитка — работа Павла, не агента. Не переписывай их по своей инициативе.
- **В кейсе про тикет-систему разделы идут «Этап 2», «Этап 3»** — первого нет и в оригинале.
  Решено оставить как есть.
- **8.8 МБ картинок в репозитории**, два PNG около мегабайта. Решено не пережимать:
  `astro:assets` всё равно генерирует avif для отдачи, а лосси-сжатие источника ухудшит
  производные.
- **У обложки в карточке кейса пустой `alt`.** Картинка лежит внутри ссылки, где компания и
  заголовок уже есть текстом; непустой `alt` заставил бы скринридер озвучить их дважды.
  Критерий AC-4 это исключение описывает явно.
- **Гамбургер-меню на мобильном нет.** В шапке три элемента, они помещаются на 390px.
- **Фавиконки нет, портрет грузится лениво, `.nojekyll` не создан, OG-превью у всех кейсов
  общее.** Обсуждалось, отложено осознанно. Подробности в `.superpowers/sdd/progress.md`.

## Деплой

`.github/workflows/deploy.yml` публикует на Pages при пуше в `main`, но только после
зелёных unit и e2e. `ci.yml` гоняет тот же набор на pull request — на push в main он
намеренно не висит, чтобы не дублировать работу деплоя.

При падении e2e отчёт Playwright сохраняется артефактом на 7 дней.
